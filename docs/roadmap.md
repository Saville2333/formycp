# Cthulhu Table 六阶段开发清单

> 原则：每个阶段结束时，项目都能直接用 `启动本地预览.bat` 打开；不留下 TODO、假按钮或不可运行的半成品。  
> 依赖顺序经过调整：**第二阶段先把车卡规则引擎做扎实，第三阶段再接 API 与 AI 自动车卡**，避免规则校验依赖模型输出。

## 阶段 1 · 应用外壳与本地数据层（已完成）

**目标**：建立可运行的纯前端单页应用、视觉系统、路由与持久化底座。

- [x] `index.html` + 六页面 Hash 路由 + 响应式侧栏
- [x] 暗黑克苏鲁设计系统、原创 SVG 印记、空状态/Toast/Dialog
- [x] `storage.js`：localStorage + IndexedDB + 内存降级 + 自检
- [x] 角色基础校验、示例调查员、档案预览、JSON 导出、删除
- [x] 完整备份导出、五份 JSON Schema、数据模型文档
- [x] 桌面 / 390px 移动端实机回归，无控制台异常

**验收**：启动页可收起；示例角色可载入；刷新后仍存在；存储自检通过；浏览器控制台无报错。

## 阶段 2 · 角色管理、规则引擎与本地车卡

**目标**：不依赖任何 API，完成一份严格符合 CoC 7e 的角色卡。

新增文件：

- `js/character.js`：属性骰、年龄修正、MOV、DB / Build、技能基础值、职业模板、点数校验、Markdown 导出
- `js/occupations.js`：职业模板与信用评级区间（也可以合并进 `character.js`，视体量决定）
- `js/character-ui.js`（可选）：角色表单与车卡工作台，避免 `app.js` 继续膨胀

任务：

1. 角色 CRUD 表单：全部人设字段、PL / NPC 切换、多角色管理。
2. 八属性随机骰：3D6×5 与 (2D6+6)×5；幸运 3D6×5；15–19 岁幸运取高。
3. 年龄修正：15–19 / 40–49 / 50–59 / 60–69 / 70–79 / 80+ 的 STR/CON/DEX/APP/EDU/MOV 调整。
4. 派生值：HP、MP、SAN、MOV、DB、Build；所有边界与查表单元测试。
5. 职业模板：侦探、记者、医生、教授、神父、古董商、警察、黑帮、艺术家等，含本职技能与信用区间。
6. 技能点：职业点 EDU×2、兴趣点 INT×2；严格校验总和、单项范围、信用评级。
7. 三种入口：随机骰点、手动分配、从已有角色复制。
8. 导入 / 导出：角色 JSON、Markdown 人设卡。
9. 车卡结果一键写入角色卡并持久化。

**验收**：每一条衍生值与手算一致；点数超额时明确阻止保存；导入坏 JSON 有可读错误；刷新后数据仍在。

**规则出处**：CoC 7e 核心规则书 · 第三章「创建调查员」及角色表。

## 阶段 3 · API 配置、流式对话与 AI 自动车卡

**目标**：打通 OpenAI 兼容接口，并把第二阶段的规则引擎接上 LLM。

新增文件：

- `js/api.js`：配置管理、请求组装、SSE 解析、超时/重试、日志
- `js/api-settings.js`（可选）：接口管理 UI
- `js/auto-character.js`（可选）：提示词、严格 JSON Schema、校验重试

任务：

1. 多套配置：名称、baseURL、API Key、Model、Temperature、Max Tokens、Top P、Stream。
2. 连通性测试；配置切换与删除；配置损坏时的降级。
3. 前端 `fetch` 直连；SSE 流式解析、逐字渲染、AbortController 中止。
4. 自定义请求头 JSON 与额外请求体 JSON；解析失败给出中文错误。
5. 联网开关：按服务商组装 `tools` / header / body；可配置。
6. API 日志：耗时、Token 用量、状态、错误摘要；写入 IndexedDB。
7. AI 自动车卡：人设 → 严格 JSON → `character.js` 校验 → 失败带错误重试 → 写入角色卡。

**验收**：无 Key 时清晰报错；流式可中途停止；接口错误不破坏本地数据；AI 车卡不超额、不越界。

**隐私**：Key 只存 localStorage；备份导出必须再次警告。

## 阶段 4 · 骰子引擎、检定与跑团桌面

**目标**：让桌面真正“跑”起来。

新增文件：

- `js/dice.js`：表达式解析、骰子、奖惩骰、CoC 检定、SAN/伤害
- `js/chat.js`（可选）：消息渲染、聊天分组、暗骰

任务：

1. 表达式：`1d100`、`3d6`、`2d6+6`、`1d8+1d4+2`、`4d6k3`、括号与加减。
2. 奖励 / 惩罚骰：1–2 个；展示所有候选十位与最终结果。
3. CoC 检定：大成功 1、极难、困难、常规、失败、大失败（96–100；技能 ≥50 时 100）。
4. 对抗检定、SAN 检定与损失表达式（1/1d6）、临时性疯狂、伤害/重伤/濒死。
5. 幸运消耗与技能成长标记。
6. 聊天卡片、暗骰、聊天记录按角色/场景分组。
7. Enter 发送、Shift+Enter 换行；移动端键盘避让。

**验收**：关键概率与边界用例通过；奖惩骰结果可复核；检定卡片能作为上下文传给 KP。

---

## 阶段 5 · 模组导入、检索与 AI 守秘人

**目标**：AI KP 严格依据模组推进，而不是自由续写。

新增文件：

- `js/module.js`：导入解析、章节/场景/线索/NPC 树、倒排索引/TF-IDF
- `js/module-ui.js`（可选）：结构编辑器与线索标记
- `js/kp.js`：系统提示词、状态机、上下文组装、信息释放控制

任务：

1. 导入 `.txt` / `.md` / `.json` / 粘贴；编码与超长文本处理。
2. 按标题层级切分章节—场景—线索—NPC；可手动修正、标记关键线索、必须触发事件。
3. 分块与关键词倒排 / TF-IDF 检索；每回合取 2–5 个相关段落。
4. KP 内部状态 JSON：当前章节/场景、已到场景、已获线索、已触发事件、NPC 态度、时间线、未解锁内容。
5. 系统提示词硬约束：只依据模组、禁止提前泄底、不替玩家掷骰/做决定、信息释放节奏。
6. 每回合组装：系统提示 + 检索片段 + 状态 + 角色摘要 + 最近 N 轮 + 骰子结果。
7. 剧情进度条、线索笔记本。

**验收**：问及未解锁内容时 KP 拒绝透露；玩家偏离主线时能被合理引导；上下文长度可控。

## 阶段 6 · 存档、日志、整合与发布

**目标**：从“能玩”到“可以长期开团”。

任务：

1. 整战役存档导出 / 导入；版本迁移与冲突处理。
2. 聊天记录重命名、删除、导出；按场景分组。
3. API 日志面板：耗时、Token、错误、请求摘要（不记录 Key）。
4. 首屏示例战役与完整空状态引导。
5. 移动端回归、键盘与读屏检查、减少动效。
6. GitHub Pages 发布检查：相对路径、`.nojekyll`、无控制台错误。
7. 最终 README、部署说明、版权与隐私声明。

**验收**：导出再导入后战役完整恢复；日志不泄露密钥；桌面/移动端主流程可走通；GitHub Pages 线上可用。

---

## 每阶段的完成定义

- 所有新增模块通过语法检查；
- 不引入构建链、不引入需要联网的外部 CDN；
- 关键规则写中文注释并标注规则出处；
- 至少验证桌面 1440px 与移动 390px；
- 控制台无未捕获异常；
- 后续阶段需要的 Schema 同步更新；
- 不留下 TODO、假按钮或“点不动的演示”。
